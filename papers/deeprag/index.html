02 · Intuition

检索不是默认动作，
而是一个原子决策。

先用熟悉的信息推进推理，遇到知识缺口才搜索。这个节奏，就是 DeepRAG 想让模型学会的“知识边界”。

论文中的例子 · Figure 1
“指环王三部曲总时长是多少？”需要先找出三部电影，再分别确认时长，最后相加。不是每一步都值得搜索。
已知：三部曲包含三部电影。
未知：每部电影的准确 runtime，需要检索。
可推理：拿到三个时长后，直接求和即可。

03 · How It Works

把 RAG 写成
一个 Markov Decision Process。

状态包含“原问题 + 已生成的子问题/中间答案”；动作包含“继续/停止”和“检索/内部知识”两层决策。

选择一个动作动作会改变状态，并影响总检索成本。
Component 1

Binary Tree Search

每个子问题分出两条路：直接使用参数化知识，或检索外部文档。优先队列按 retrieval count 探索路径，找到正确且成本最低的轨迹。

Component 2

Imitation Learning

用最优轨迹训练 DeepRAG-Imi，让模型同时学习子问题生成、中间答案和检索时机。

Component 3

Chain of Calibration

离线用偏好对微调，在线用 outcome-based reward 自我探索，校准模型对“我知道什么”的判断。

04 · Deep Dive

奖励函数把两个目标
放到同一张账单上。

正确答案优先；在正确的前提下，检索越少，奖励越高。这正是“自适应”的数学来源。

Equation 3 · Online calibration
R = 1 − α × min(T, T(sₜ₊₁))
当答案正确时，奖励随实际检索次数下降；格式错误得 0；答案错误不会因为少检索而获得“便宜的高分”。
R = 0.80在答案正确、T = 5 的示例预算下。
Equation 1 · Imitation learning
L = − Σ log [ Pr(qᵢ|sᵢ₋₁) + Pr(aᵢ|sᵢ₋₁,qᵢ,dᵢ) ]
训练目标同时关注“问什么”和“怎么回答”。dᵢ 在该步未检索时为 null，帮助模型学会按需接入文档。
qᵢ：第 i 个子问题
aᵢ：中间答案
sᵢ₋₁：此前累积的推理状态
Advanced · Offline calibration

DPO-style objective 比较 direct answer 与 retrieved answer 的偏好，β 控制相对于 reference model 的偏离惩罚。在线版本则采用 GRPO，并对 retrieved tokens 使用 masked loss。

◫

06 · Critical Thinking

结论、证据与
仍然未知的部分。

下面把“论文确实展示了什么”和“读者仍需保持的谨慎”并列放在一起。

Claims · 论文主张

按需检索能同时提升多跳 QA 的准确率与检索效率；模型更能探索自身的知识边界。

Supporting evidence · 论文证据

五个 benchmark、两种 backbone、OOD 结果、retrieval count、balanced accuracy / MCC，以及 imitation / calibration ablation。

Remaining uncertainty · 读者可追问

论文在结论中强调未来开源代码；对不同 retriever、长文档噪声和更开放的生成任务，稳健性仍需更多验证。

研究者视角
最强贡献：把检索时机、子问题生成和终止决策放进同一条可训练轨迹。
关键设计：以“正确答案 + 低检索成本”为搜索目标，而非单纯增加 context。
值得质疑：奖励和最优路径依赖 retriever、最大检索预算 T 与答案判定方式；换环境后决策边界可能移动。

Explain it yourself

1. 为什么第一步可以不检索，第二步却要检索？

正确。DeepRAG 的核心不是“多搜”，而是让检索决策与知识边界对齐。

2. Binary Tree Search 的两条分支是什么？

正确。每个子问题都可走内部知识分支或外部检索分支。

3. 为什么“retrieve only”不一定最好？

正确。论文 Figure 5 指出，持续检索会增加成本，也可能把噪声带入上下文。
