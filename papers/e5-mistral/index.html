01 / The central idea

把 LLM 的两种能力接起来

文本向量把一段文字压缩为一组数字。检索时比较向量，就能在大量文档中快速寻找与任务相关的内容。

问题 / THE BOTTLENECK

好向量，常依赖复杂的数据管线

传统强基线往往先用海量弱监督文本对做对比预训练，再用标注数据微调。收集、过滤与组织这些数据，需要额外工程；任务和语言覆盖也受限。

思路 / TWO ROLES

一个模型造数据，另一个学表示

GPT-4 / GPT-3.5 负责生成丰富的任务与样本；已预训练的 Mistral-7B 负责学习向量。把生成能力转成监督信号，把语言知识转成检索能力。

结果 / A SHORTER RECIPE

省掉额外的对比预训练阶段

从预训练 Mistral 出发，直接做一次对比微调。仅合成数据已经有竞争力；混合公共训练集后，达到论文当时比较中的领先水平。

核心转变：先定义“什么关系值得被拉近”，再训练向量去表达这种关系。

依据：§1、§3 · 研究问题与方法。这里的“少于 1,000 步”仅指微调阶段；基础模型已经完成大规模语言预训练。

02 / Data is the interface

先想任务，再写训练样本

只让模型反复“写一个检索例子”，容易得到相似的数据。作者先扩大任务池，再按具体任务生成样本。

STEP 01 / BRAINSTORM

生成任务定义

让 LLM 构思一批用途，例如“给定科学主张，寻找能验证或反驳它的文档”。任务应能产生许多不同查询。

LANGUAGE MIX

覆盖 93 种语言，分布并不均匀

英语占 43.1%；语言按带权概率采样。后 75 种低资源语言平均各约 1,000 个样本，覆盖广度与数据密度是两回事。

GENERATION MIX

多样性来自任务、模板与采样

约 75% 样本由 GPT-4 生成，25% 由 GPT-3.5 生成；总消耗约 1.8 亿 tokens。格式检查与去重能清理数据，但不能保证每条语义关系都正确。

03 / Relevance needs a task

同一句查询，任务可以不同

“语义接近”不只有一种含义。把自然语言任务指令加在查询前，告诉模型这一次应该寻找哪种关系。

INTERACTIVE / 指令实验

这次，你想找什么？

Instruct: 查找与给定句子含义相近的表达。 Query: 这家餐厅太让人失望了。

文档侧直接编码原文，不加任务前缀。改变查询指令时，可以复用已建好的文档向量索引。

寻找同义表达时，目标是保留整句话的意思；“负面评价”只保留了情感类别。
SAME DOCUMENT COLLECTION

同一组候选，目标关系改变

这家餐厅的体验糟透了。任务正例
负面评价任务正例
这家餐厅令人非常满意。

概念演示：高亮表示人为指定的目标关系，不是实际模型检索排名。

指令放在查询侧，让“本次任务”进入向量；文档索引保留复用价值。

依据：§3.2 · Equation 1。合成数据使用生成的任务定义；公共训练集使用作者编写的指令。

04 / Turning a generator into an encoder

用一个向量，学会区分正负例

训练目标从“预测下一个词”切换为“让查询与正确文档靠近”。这里用的是标准对比学习。

ENCODING / EOS POOLING

末尾位置，汇聚前面的信息

查询和文档分别送入同一个模型。每段输入末尾添加 EOS，取末层 EOS 的 hidden state 作为整段文本的表示。

Instruct …Query …[EOS]
→ hq ∈ ℝ⁴⁰⁹⁶
Document …[EOS]
→ hd ∈ ℝ⁴⁰⁹⁶

因果注意力下，末尾 EOS 能看到前面的输入。论文采用 last-token pooling；与网站中的 NV-Embed 不同，本篇没有引入 latent attention pooling。

OBJECTIVE / INFONCE

拉近正例，也拉开容易混淆的负例

s(q,d) = cos(hq, hd) / τ
L = −log [ eˢ⁺ / (eˢ⁺ + Σn ∈ N eˢⁿ) ]

正例贡献分子；正例与所有负例共同构成分母。正例的相对分数越高，损失越小。

批内负例：同一 batch 中其他样本提供的候选。
困难负例：看似相关，却不满足当前任务的文本。

论文温度 τ = 0.02；完整配方中每个查询配置 1 个困难负例。合成模板没有产生负例时，训练数据配方还涉及负例挖掘。

打开对比学习小实验：温度如何改变“分数差”的影响？

固定正例相似度为 0.80，普通负例为 0.30。调整困难负例，看它靠近正例时，正例的 softmax 概率如何下降。

低温度会放大相似度差异：正例领先时更自信，困难负例反超时也会带来更大惩罚。

仅按上方公式计算的三候选示意；不是训练曲线，不运行模型，也不预测 benchmark 分数。

06 / Where the claims stop

读懂亮点，也读懂边界

论文展示了一条简洁有效的训练路线。实际选型还需要衡量语言、文档长度与部署成本。

01 / MULTILINGUAL

93 种语言，不等于全面领先

MIRACL 的 16 语言平均 nDCG@10 为 62.9，低于 mE5-large 的 66.5。英语等部分高资源语言表现强，低资源语言仍明显受基础模型能力限制。

02 / LONG CONTEXT

32k 是专项能力证据

调整滑动窗口与 RoPE base 后，模型在合成的个人 passkey 检索中，32k 范围内准确率可超过 90%。这不等于真实长文档问答或检索也达到同样水平。

§5.2 · Figures 4、5

03 / COST & DATA

训练流程简化，推理仍然昂贵

7B 模型编码成本高于常见 BERT 编码器，4096 维向量也增加存储负担。数据生成依赖闭源 LLM 与人工模板；基础模型预训练数据不透明，污染风险无法彻底排除。

07 / Check your understanding

你能把方法讲清楚了吗？

点击作答。理解下面三点，就抓住了本篇论文最容易混淆的地方。

01 · GPT-4 在这篇论文中扮演什么角色？

GPT-4 / GPT-3.5 生成监督数据；实际向量模型从 Mistral-7B 微调而来。

02 · MTEB 66.6 分对应哪种设置？

66.6 属于 full data；仅合成数据的 MTEB 平均是 63.1。

03 · 为什么只在查询侧添加指令？

文档原文通过同一个向量模型编码；查询带上任务定义，文档侧无需随任务改变而重建索引。
